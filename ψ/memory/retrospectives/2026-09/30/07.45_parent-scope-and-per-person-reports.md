## AI Diary

The scope gap was mine. I ported this bot's query handlers, wrote a helper
(`getDataScope`) whose own comment promised "parent sees family-wide data,
same as web app", and then never checked that every query path actually used it.
ดูยอด slipped through with a hardcoded filter and would have stayed broken
indefinitely — the bug only surfaced because the user happened to ask a direct
question about parent visibility. I shipped a "full feature set" that was
secretly missing a guarantee, and my verification (4-step pipeline, sandbox
tests) never tested parent-vs-child scoping at all, because I only ever tested
as Lita, a child. Role-based behavior needs at least one test per role; I had
zero for parents at that point.

Second: my first fix chose a display format — `(owner)` suffixes — that the
user replaced one turn later with per-person sections. I picked it by feel
instead of showing a 5-line mock preview and asking. The redo was cheap this
time; the habit is not.

## Honest Feedback

1. **I verified the bot as a child only.** Every sandbox pipeline test this
   whole migration ran as Lita (child). Parent-specific behavior — scoping,
   link-code minting, family roll-ups — was never exercised until the user
   asked. A "full feature set" claim with zero parent-path tests was
   overconfidence, not completeness.
2. **The PrismaPromise mock quirk bit me twice.** The named-const + `as never`
   pattern is already in project memory from yesterday, and I still wrote the
   inline `mockImplementation(async (args: any) => ...)` first, hit the tsc
   error, then fixed it. Knowing a pattern and applying it at write-time are
   different skills; I need to reach for it on the first keystroke, not after
   the compiler complains.
3. **I guessed the display format.** "(Lita)" suffixes vs "👤 Lita" sections —
   a 30-second ASCII preview in my reply would have let the user pick before
   I committed a format, deployed it, and written docs for it. The redo cost
   was one cycle, but it was a self-inflicted cycle.

## Lessons Learned

1. Role-based behavior needs at least one test per role — testing only as one
   role is testing half the contract.
2. When a shared helper encodes a policy ("parent sees family-wide"), grep for
   call sites that bypass it before declaring the feature done.
3. For user-facing report formats, show a mock preview first — format is a
   preference, not a technical decision.
