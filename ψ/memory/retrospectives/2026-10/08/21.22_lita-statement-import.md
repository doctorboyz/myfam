3. **Monthly allowance gets its own income category** (ค่าขนม/เงินรายเดือน) — matches the 12th-of-month transfer pattern from สุรางค์รัตน์.

(2) The psql failures were self-inflicted: I'd already learned the snake_case/PascalCase convention in a previous session and re-made the mistake anyway — this should have been a rule I encoded, not a fact I re-derived. (3) Context compaction hit mid-task during the import design; the handoff summary was good, but I can feel how much was held together by the summary being diligent — the lesson file for the import assumptions (self-transfers = True Money top-ups) lives only in the script header, and if that assumption is wrong the fix path is buried in a commit message rather than a tracked issue.

## Lessons Learned

1. **Before importing historical rows into an account, check when the account balance was last touched** (updated_at + Reconciliation table). Balance adjustments are only safe for movements after the last touch — otherwise double-count. This is now the checklist step between dry-run and apply.
2. **Trust the data's own arithmetic over code semantics**: a dry-run that prints type-sums and reconciles against the source statement's net is the cheapest possible proof of a faithful transcription.
3. **DB access conventions for this repo**: `docker exec myfam-db psql -U myfam -d myfam`, tables PascalCase-quoted (`"Account"`, `"Transaction"`), columns snake_case (`created_by_id`, `owner_id`), `date` is naive timestamp stored at midnight-BKK semantics.
