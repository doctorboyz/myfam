## Architecture (5 ชั้น, ไฟล์เล็ก <400 บรรทัด, ห้ามทำ monolith แบบ LINE เดิม)

```
src/lib/telegram/          แพลตฟอร์ม (raw fetch, no SDK — เหมือน line.ts เดิม ~150 บรรทัด)
  types.ts (Update subset) client.ts (sendMessage/sendChatAction/getFile/download)
  verify.ts (timingSafeEqual เทียบ X-Telegram-Bot-Api-Secret-Token)
src/lib/bot/               แกนบอท
  commands.ts intent.ts extract.ts extract-slip.ts match.ts
  session.ts (DB-backed!) link.ts record.ts queries.ts reconcile.ts
  format.ts keyboards.ts
src/lib/bot/handlers/
  router.ts text.ts photo.ts confirm.ts
src/lib/transaction-mutations.ts   ← extract จาก /api/transactions POST (shared)
src/app/api/telegram/
  webhook/route.ts (thin) sandbox/route.ts (dev, guard ?key=) link-code/route.ts
```

**Key decisions**:
1. Handlers รับ `BotSender` = `(text, keyboard?) => Promise<void>` — production ครอบ
   sendMessage, sandbox/test เก็บข้อความลง array → pipeline ทั้งหมด test ได้ไม่ต้องมี network
2. **Ack-then-process ด้วย `after()` (next/server)**: verify secret → ตอบ 200 ทันที →
   `after(() => processUpdate())` — Cloudflare free tunnel ตัดที่ ~100s (524) แต่ vision
   อาจนาน 30–90s · Telegram retry non-2xx ดังนั้นตอบ 200 เสมอเมื่อ secret ผ่าน, log error ภายใน
3. **Session เก็บใน DB** (`BotSession` payload JSONB + TTL 10 นาที) — แกนจุดอ่อนสุดของ LINE
   เดิมที่ใช้ in-memory Map ตายทุกครั้งที่ deploy · failure counter (≥3 ครั้ง/5 นาที → แนะนำใช้เว็บแอป)
4. Query (ยอด/รายการล่าสุด/สรุป) แบบ **deterministic** (Prisma + `Intl.NumberFormat('th-TH')`) ไม่ใช้ AI format
5. **Reply keyboards** สำหรับเลือกบัญชี/หมวด/ทิศทาง — ปุ่มส่ง text (`เลือกบัญชี:<id>`, `เลือกหมวด:`,
   `ยืนยัน`, `ยกเลิก`, `เงินเข้า`, `เงินออก`) แล้ว parser จัดการต่อ
6. บอทเขียน **direct Prisma** (ห้ามเรียก HTTP route ตัวเอง — `/api/transactions` POST trust
   `createdById` จาก body) · soft-delete ตาม convention ปัจจุบัน (LINE เดิม hard delete — ห้ามตาม)

## Prisma (migration เดียว: `<timestamp>_add_telegram_links_and_bot_sessions`)

```prisma
model TelegramLink {
  id             String   @id @default(uuid())
  telegramUserId String   @unique @map("telegram_user_id")
  userId         String   @unique @map("user_id")
  displayName    String?
  createdAt      DateTime @default(now()) @map("created_at")
  user User @relation(fields: [userId], references: [id], onDelete: Cascade)
  @@map("telegram_links")
}

model BotSession {
  id        String   @id @default(uuid())
  userId    String   @map("user_id")
  kind      String   // 'transaction' | 'reconcile' | 'failure'
  step      String
  payload   Json
  expiresAt DateTime @map("expires_at")
  createdAt DateTime @default(now()) @map("created_at")
  updatedAt DateTime @updatedAt @map("updated_at")
  user User @relation(fields: [userId], references: [id], onDelete: Cascade)
  @@unique([userId, kind])
  @@index([expiresAt])
  @@map("bot_sessions")
}
```
- User เพิ่ม relation `telegramLink` + `botSessions`
- purge session หมดอายุใน `/api/cron/purge` ที่มีอยู่แล้ว
- สลิป (sharp resize 512px JPEG q80, ~50–150KB base64) เก็บใน session payload ระหว่าง flow
  (≤10 นาที) — กันดาวน์โหลดซ้ำ (Telegram file path หมดอายุ ~1 ชม.)

## Risks / Gotchas

1. Vision model default เป็น text model — เลือกก่อน Phase 3 + kill switch degrade ("พิมพ์รายละเอียดแทน")
2. Cloudflare ~100s → `after()` บังคับ, ห้าม await AI ใน request
3. Telegram retry non-2xx → ตอบ 200 เสมอเมื่อ secret ผ่าน
4. Balance drift → Phase 0 regression test ห้ามข้าม
5. Telegram ส่งรูป recompress (~1280px) — สลิปเบลอ vision ตก → ตอบ gracefully
6. "ยืนยัน" ไม่มี session → "ไม่มีรายการรอยืนยัน"
7. Sandbox ต้องมี key guard · ห้าม log token/secret
8. Prisma Decimal → `Number()` ก่อนคิด/format
9. Timezone: ใช้ `src/lib/timezone.ts` (Bangkok) — ห้าม UTC `toISOString().split('T')[0]` (เพี้ยนก่อน 07:00)
10. Update ไม่เรียงลำดับ — family bot ยอมรับได้ (upsert last-writer-wins)
